# 踩坑清单

这份清单里的每一条都是真实撞过的，不是预想的。做同类工作台前先扫一遍。

## 一、读 xlsx（浏览器侧）

**1. 千帆导出的 zip，局部文件头里的 size 是 0。**
只按局部头（Local File Header）取压缩大小会解压出空文件。
→ **尺寸一律从中央目录（Central Directory）读**，`zip-read.js` 已按此实现。

**2. 浏览器没有 `wx.getFileSystemManager().unzip`。**
小程序能直接 unzip，网页里没有这个 API。
→ 自己解析 EOCD → 中央目录 → 局部头，再用 `DecompressionStream('deflate-raw')` 解压。
注意对 `stored`（未压缩）条目要直接取字节，不能走解压。遇到不支持 `DecompressionStream` 的环境，
要给出明确提示而不是静默出空数据。

**3. xlsx 单元格取出来是字符串。**
数字转换是 `ingest.js` 的职责，解析层不要提前 `Number()`，
否则空值和 0 会被混在一起（「没填」和「填了 0」在缺价判断里含义完全不同）。

## 二、表头与取值

**4. 表头行识别时，空单元格必须跳过。**
`'任意字符串'.indexOf('')` 恒为 0——不跳过空值的话，一行全空的行会被判成「命中所有必需列」。
同时用「命中必需列数 → 非空格数」两级比较，避免多个候选行并列时选错。

**5. 不要用 `replace(/\s+/g,'')` 做通用清洗。**
它会把支付时间「2026-09-22 14:33」中间的空格压掉。
→ 归一化列名时压空白；取值时只 `trim` 保留内部空格。

**6. 真实导出文件前面常有标题行**（如「导出时间 2026-09-05」），
不要假设第一行是表头——在前 10 行里找。

## 三、口径与降级

**7. 收入主列用错会系统性算错。**
必须用「商家应收金额(元)（支付金额）」；用「用户实付金额」会把平台补贴算成商家损失。
详见 `核算口径.md`。

**8. 平台扣费与推广费，订单表里根本没有。**
不要假设一个佣金比例、也不要按行业均值编一个——那是在给用户一个假的精确数。
→ 让用户手填；不填按 0，并在文案里说明「利润是上限估值」。

**9. 零成交的规格必须建卡片，不能只写进一行提示文字。**
早期版本把「参数表里有、本期没成交」的款只放进预警文字里，结果：
「哪些款一件没卖」这个最该被处理的信息等于看不见，而且建议价规则里的**滞销款分支永远走不到**。
参数表本身就是店主的在售清单，数量可控，全部建卡片。

**10. 「缺拿货价 → 利润虚高」只对本期真有成交的款说。**
零成交的款没有利润可言，对它说「利润虚高」是无意义噪音。

**11. 月度利润只是分摊值。**
拿货价 / 平台扣费 / 推广费都是整期一个数，没有月度粒度。
按销售额占比摊到各月可以，但**必须在界面上标明是分摊**，否则会被当成真实月度利润做决策。

## 四、交互与存档

**12. 换了数据源后必须重算。**
真实 bug：拖入新文件后只更新了状态没调 `compute()`，画面停在旧快照上，
直到用户去动一下费用参数才刷新。凡「改变输入」的路径都要显式走到重算。

**13. 本地存档不能被空数据覆盖。**
真实缺陷：`save()` 原来无条件覆盖最新快照，传入一个没有 `kpi` 字段的对象就把上期好数据冲掉了。
→ 校验必需字段，不合格直接拒绝写入并返回失败。

**14. 微信 storage 单个 key 上限 1MB。**
存档订单要按**真实字节数**判断（中文一个字 3 字节，按字符数会严重低估），
超限就不存订单、只存结果，并告知「重算需要重新传表」。

## 五、产品形态（最容易白做的地方）

**15. 先问用户要什么，别按「更完整」的方向堆功能。**
本项目第一版做了身份验证 + 访客/店主双态 + 决策留痕 + 跨期复盘 + 数据文档页，
用户一句话全部推翻：「不需要身份验证，就是要有地方传 excel，这个软件也不存在决策的问题，
它只是数据汇总算出利润和建议价格」。**功能做多了不是加分，是返工。**

**16. 数据入口不能藏。**
藏进二级页、或卡在登录后，用户会直接反馈「数据传输不进去」。
入口放最顶层，并把「电脑导出 → 微信文件传输助手 → 手机选文件」这类小程序读不到电脑硬盘的
前提写清楚——但**不要写成三步引导大卡片**，用户会嫌复杂；一行状态文字足够。

**17. 提醒类区块容易变成噪音。**
做过的黄底「口径提醒」区块被用户直接要求删掉。
→ 提醒放到**它对应的那张卡片里**（缺拿货价 → 该款的卡片上写「成本按 0 算，利润是虚的」），
不要单独做一块集中栏。

**18. 单文件 HTML 是最适合分发的形态。**
小程序要先发布才能给别人用，还要开登录开关、绑定账号，卡点多；
网页版单文件发过去双击就开，不需要服务器、登录、网络。除非明确要手机端，否则别上小程序。

**19. 测试失败先分清是「代码错」还是「断言错」。**
本项目多数失败是断言里的期望值自己算错了（成本漏算某款件数、列号数错），
改代码之前先手算一遍期望值——否则会把对的引擎改坏。
